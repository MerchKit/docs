# Exporting Channel Data

Once your channel content is generated and validated, you're ready to export and submit to the marketplace. Use a connected integration to send records to its destination, or download a CSV/TSV file for review and submission.

## Export Overview

Choose the workflow that matches your destination:

1. Review the products and destination mapping.
2. Select the intended products.
3. Use **Export** to start a connected integration workflow or download a CSV/TSV file.
4. Check the results in Merchkit and the destination before treating products as live.

A catalog download is not guaranteed to match every marketplace’s upload template. A completed integration job can contain rejected products. See the destination walkthroughs below for Shopify and Wayfair.

## Step 1: Prepare for Export

- Your workspace must have the destination integration connected and configured. Review its [export mapping](/product/integrations-and-field-mapping/setting-up-export-mapping) before writing to a live store.
- You need export permission (`data.export`). Editing product values and integration settings requires their respective permissions.
- Check which products and fields you intend to send. Test a small selection before a large update.
- For Wayfair, confirm the intended environment, supplier configuration, product class and channel attributes with your integration administrator. Do not assume a test connection writes to production.

Use the [pre-export checklist](/product/channels-and-content-generation/pre-export-validation) to review the data. Exporting can update live platform records; a successful Merchkit job does not guarantee marketplace acceptance or storefront visibility.

Before exporting, confirm:

- [ ] All required fields are filled
- [ ] Validation shows no critical errors
- [ ] You've spot-checked a sample of products
- [ ] You're exporting the right products (filtered/selected correctly)

If not, go back to [Pre-Export Validation Checklist](/product/channels-and-content-generation/pre-export-validation) and fix issues first.

## Step 2: Select Products to Export

You can export:

### Option 1: Export All Products in Channel
For a file download, **Export → Export All → CSV** or **TSV** exports the current filtered set. Review active filters; “all” does not necessarily mean the entire catalog.

### Option 2: Export Selected Products
Select specific SKUs with row checkboxes. For a file, use **Export → Export Selected → CSV** or **TSV**. For a connected integration, choose the connection name and mapping template where offered.

**Use this when:**
- You're doing an incremental update (only new products)
- You want to test with a small batch before full export
- You're updating a specific category

### Option 3: Export Filtered Products
For CSV/TSV, **Export All** uses the current filters. Shopify’s select-all selection also resolves products using the current filter model and exclusions. For Wayfair, use explicit row selections; do not assume it interprets select-all filters like Shopify. A saved view is not a permanent list of products.

## Step 3: Click the Export Button

Use **Export** in the table toolbar. Connected integrations appear when products are selected and you have export permission. If a connection has multiple mapping templates, choose the intended template from its submenu.

For file downloads, choose **Export Selected** or **Export All**, then **CSV** or **TSV**. For an integration, choosing the connection starts its export workflow; it does not download a file for a later manual upload.

## Step 4: Download the File

Follow the file-export job and retrieve its output when ready. Check your browser’s download location. Give saved copies clear names such as `Wayfair_2026-10-10_v1.csv`; this is an organizational suggestion, not a guaranteed generated filename.

TSV separates columns with tabs; tabs and line breaks within a value become spaces.

## Step 5: Verify the Download

Before uploading to the marketplace:

1. **Open the file locally** — Use a spreadsheet or text editor
2. **Spot check a few rows** — Make sure products look correct
3. **Check row count** — Does the number of rows match your expected product count?
4. **Look for encoding issues** — Special characters should display correctly (not garbled)

[SCREENSHOT: CSV file open in Excel showing product data]

Check that spreadsheet software has not changed leading zeros in identifiers, date formats or numeric values. Keep the original export before resaving. Confirm headers and values match the destination’s current upload template.

## Step 6: Submit to the Marketplace

For manual file submission, use the marketplace’s import workflow and inspect its result. For connected Shopify and Wayfair workflows, follow the walkthroughs below; they submit directly from Merchkit.

### Submission Process by Marketplace

**Wayfair:** Use the [connected export walkthrough](#submit-products-to-wayfair) below. Its create/update handling, error reporting and processing stages differ from a manual file upload.

**Amazon:**
1. Log in to Seller Central
2. Go to **Inventory → Uploads**
3. Choose **Feed Type** (Inventory, Product, etc.)
4. Upload your file
5. Amazon processes and confirms
6. Check **Performance → Listings** for any issues

**Walmart:**
1. Log in to Walmart Seller Center
2. Go to **Catalog → Item Setup**
3. Upload your feed
4. Walmart validates and returns any errors
5. Confirm items in your Dashboard

**Google Merchant:**
1. Log in to Google Merchant Center
2. Go to **Feeds**
3. Create or update your product feed
4. Upload CSV
5. Google validates; check **Diagnostics** for errors

**Shopify:** Use the [connected export walkthrough](#export-a-shopify-tag-update) below. Connecting Shopify does not by itself enable automatic synchronization. If using a manual CSV import instead, follow Shopify’s current import template and review matching behavior before updating existing products.

**Mirakl (custom marketplaces):**
1. Access the specific marketplace's seller portal
2. Look for **Product Feed** or **Catalog Upload**
3. Upload your file
4. Marketplace validates and confirms

Different marketplaces have different processes. Check their documentation for specific steps.

## Export a Shopify tag update

Suppose you have reviewed a collection's seasonal tags and want to send them to your connected store.

1. Open **Products** or the relevant channel grid. Check the product identities and the tag values you intend to send.
2. Review the Shopify export mapping and choose the intended template if your workspace has several. Hiding a column in the grid does not remove it from an integration mapping.
3. Select a small group of products with the row checkboxes.
4. Click **Export** in the table toolbar, then choose your Shopify connection's name. If it has multiple export templates, choose the intended template from its submenu.
5. Follow the job progress and inspect any errors. Check the same products in Shopify to confirm the tags and other mapped data are correct.
6. Once the sample is correct, select the intended larger batch and repeat the export.

The export workflow handles batching, parallel work and Shopify rate limits; there is no speed setting to enable. Duration varies with the number of records, mapped data and channel limits. The timing example in the [changelog](/changelog) is one pre-release test, not a completion-time guarantee.

Only select-all Shopify exports use the current filter model to resolve the selected set. Review the selection count and any exclusions before starting; a saved view is not a permanent list of products. Do not assume an export sends only cells changed since the previous run.

### Shopify troubleshooting

- **The connection is missing from Export:** select products first, then check the connection and your export permission.
- **Unintended fields changed:** review the selected mapping template. Removing a column from view does not remove its export mapping.
- **An image did not export:** images without a usable URL are skipped rather than failing product creation. Fix the source image URL before retrying.
- **An export is taking longer than expected:** check job progress and channel errors before starting a duplicate run. Larger payloads and rate limits affect duration.

## Submit products to Wayfair

1. Open the relevant product or Wayfair channel grid and review a small sample's category, supplier part number, values and images.
2. Select the individual product rows to send. Use an explicit selection for this workflow rather than assuming a select-all filter will be interpreted like Shopify's.
3. Click the toolbar's **Export**, then choose your Wayfair connection's name.
4. Follow job progress. The export determines whether to create or update each product from its saved Wayfair identity. Do not clear that identity simply to retry an update.
5. Read the completed job's exported and error counts. Inspect the **Status** column for rejected products and follow [Resolving export errors](/product/channels-and-content-generation/feed-validation-errors).
6. After acceptance, verify the product in Wayfair. Its processing and visibility can lag behind the Merchkit job.

For new products, required images are included in the initial create submission. Provide valid image URLs in the channel's mapped image attributes before exporting. Multi-select answers are sent as separate ranked values; use the attribute's supported options rather than inventing a joined value.

Submission IDs and statuses are retained for tracing while Wayfair processes the request. This is not a promise of immediate marketplace visibility or a separate customer-facing submission-history screen. If a request is accepted but the product is still missing, provide the job and product identifier to support for tracing before repeatedly creating it again.

A job marked completed can contain rejected records. Read its result counts; reaching 100% means the workflow finished, not that every product became a live listing. Successful retries clear previous export errors for the products that pass.

## File Storage and Version Control

After exporting, consider:

1. **Keep exports organized** — Save by date and channel
   - `exports/Wayfair_2026-04-05.csv`
   - `exports/Amazon_2026-04-05.csv`

2. **Version your files** — If you make multiple attempts, version them
   - `Wayfair_v1.csv`, `Wayfair_v2.csv` (if issues found)

3. **Archive old exports** — Keep successful exports for record-keeping
   - Useful if you need to revert or compare versions

## Export Frequency

How often should you export?

- **Initial launch** — Export immediately to populate the marketplace
- **Weekly/monthly** — Regular updates to keep listings fresh
- **After product changes** — When you update descriptions, prices, or images in Products view
- **Seasonal changes** — Before peak seasons, update availability and inventory
- **Continuous** — If your team separately configured API automation, confirm its schedule and monitor its results. An integration connection alone does not enable automatic exports.

## Automating Exports (API)

Use an API integration when you need repeated exports or a large catalog workflow. First configure the connection and its export mapping, then test a representative selection.

A connected integration makes an export destination available; it does not mean every catalog edit automatically syncs. If your team has built scheduled or event-driven automation, confirm what triggers it, which products and fields it sends, and how failures are monitored. Avoid overlapping automated runs and manual retries until you understand the previous result.

## Troubleshooting Export Issues

### Issue 1: File Won't Download
- Check your browser's download settings
- Check the export job’s result before retrying; CSV and TSV downloads are available
- Check blocked downloads and the browser’s download location
- Try a smaller representative selection to isolate a large-export problem; keep the job identifier for support

### Issue 2: Special Characters Look Wrong
- This is usually an encoding issue
- Check the encoding and delimiter selected when importing the file into your spreadsheet
- Open in a text editor (not Excel) to verify encoding

### Issue 3: File Format Doesn't Match Marketplace Requirements
- Confirm you've selected the correct format for that marketplace
- Check the marketplace's documentation for required format
- Contact Merchkit support if the format isn't available

### Issue 4: Rows or Columns Missing from Export
- Review the actual row selection, active filters and expected exported headers
- If specific products aren't exporting, check if they've been filtered out
- Verify that the channel grid actually contains those products

## Next Steps

After you've submitted your feed to the marketplace:

1. **Monitor for acceptance** — Most marketplaces email confirmation or errors within hours to days
2. **Check your marketplace dashboard** — View your live listings
3. **Address any rejections** — If the marketplace rejects the feed, see [Feed Validation & Error Resolution](/product/channels-and-content-generation/feed-validation-errors)
4. **Optimize continuously** — See [Continuous Optimization](/product/channels-and-content-generation/continuous-optimization) to improve listing performance

Confirm the destination has accepted the records and made the listings visible. Completion of a Merchkit export or file download alone does not establish that products are live.
