# Resolve export errors

If Wayfair rejects a chair, start with the affected product and field rather than changing unrelated attributes or resubmitting the whole assortment.

## Before you start

You need access to the exported products and job results. Correcting a product value requires edit permission; retrying the integration export requires `data.export`. Keep the supplier information and the destination's accepted values available for comparison.

The **Status** column described here surfaces recorded errors. It does not guarantee that every marketplace requirement has been checked before export.

## Find and fix a Wayfair rejection

1. Read the finished export job's result counts. A completed job can include products that failed validation.
2. Find an affected product in the catalog grid and inspect its **Status** column. Open the error indicator to see the affected attribute names.
3. When an attribute is identified, select its name to bring the column into view. Inspect the cell's **Errors** information. Some errors remain under **Integration Errors** when they cannot be tied to a specific attribute.
4. Read Wayfair's original response as well as any added guidance. Compare the value with the supplier information and the allowed values for the product's Wayfair class.
5. Correct the value, then select that product and export through the same Wayfair connection again. See [Submitting products to Wayfair](/product/channels-and-content-generation/exporting-channel-data#submit-products-to-wayfair).
6. Check the new job's result counts and the product's error state. A successful retry clears stale export errors. Confirm acceptance and eventual visibility in Wayfair separately.

For example, an error may name a material-related attribute but contain only a technical identifier in the raw response. Start with the named field; do not substitute a guessed material simply to clear the error. If the message is still unclear, retain the raw text for support.

## Images and multi-select values

For a new product, check that the mapped channel image attributes contain valid, accessible image URLs. A missing image can cause a failed submission. Adding an image somewhere in the workspace is not enough if the export does not reference it.

For multi-select attributes, use supported options. The export sends separate ranked values to Wayfair; do not manually encode ranks or combine several options into a made-up option.

## Interpret progress correctly

- **The bar is still below 100%:** the export can still be storing errors or updating results after sending the payload.
- **The job completed with errors:** the workflow finished, but some products failed. Fix those records and retry the appropriate selection.
- **The request was accepted:** Wayfair can still be processing it. Acceptance is not proof of a visible listing.
- **An old error remains:** check whether the retry actually succeeded for that product, and refresh the catalog data if a teammate ran it. See [Shared catalog refresh](/product/getting-started/understanding-products-view#refresh-after-a-teammates-job).

## When to ask for help

If a field cannot be identified, a corrected value is still rejected, or an accepted product remains missing, share the product identifier, job, connection/environment and raw error with your support contact. Submission tracing can help distinguish a rejected request from one still being processed.

For other connected platforms, inspect the returned error and the [export mapping](/product/integrations-and-field-mapping/setting-up-export-mapping). For a file uploaded outside Merchkit, use the destination's own import result to identify rejected rows; a successful file download in Merchkit says nothing about that later upload.
